# SCHISM docker image

`docker/Dockerfile` builds a Docker image that runs [SCHISM](https://schism-dev.github.io/schism/master/) on workspaces generated by rompy-schism, so you don't need to compile SCHISM yourself.

The image is published as **`ghcr.io/rom-py/schism`**:

| Tag | Contents |
|---|---|
| `5.13.0` | SCHISM release v5.13.0 |
| `latest` | The newest release |

Pin a version tag for reproducible runs, since `latest` moves when a new release is published. Every image is tested with workspaces generated by rompy-schism before it is published.

Each image contains SCHISM built with MPI and NetCDF:

| Command | What runs |
|---|---|
| `schism` | Hydrodynamics |
| `schism_wwm` | Hydrodynamics coupled with the WWM wave model |
| `combine_hotstart7` | Merges the hotstart files that SCHISM writes per process into one `hotstart.nc` |

`schism` and `schism_wwm` use SCHISM's default output: `out2d_*.nc` and one file per 3D variable, written by scribe processes.

> [!NOTE]
> `docker/schism` builds a different image, used by the tests: several SCHISM versions in one image, built on first use. This image contains one release and is published.

## Running a generated workspace

SCHISM always runs under MPI. Its argument is the number of **scribes**, processes that only write output, and `mpirun -n` counts them too: `mpirun -n 6 schism 2` runs 4 compute processes and 2 scribes.

The image allows more processes than the machine has cores, since scribes mostly wait for output.

SCHISM needs one scribe for all 2D outputs (plus `zCoordinates`), and one more for each 3D output variable, with vectors counting as two. With too few, it stops with `Too few scribes`.

### From rompy-schism

Use rompy's Docker backend:

```python
from rompy.backends import DockerConfig

modelrun.run(
    DockerConfig(
        image="ghcr.io/rom-py/schism:5.13.0",
        executable="schism 2",
        mpiexec="mpirun",
        cpu=6,
    )
)
```

### From the command line

```bash
docker run --rm -v "$PWD":/data ghcr.io/rom-py/schism:5.13.0 mpirun -n 6 schism 2
```

## Continuing from a hotstart

With `nhot=1`, SCHISM writes the model state every `nhot_write` steps, one file per process: `outputs/hotstart_<rank>_<step>.nc`. Merge them before starting another run from them:

```bash
docker run --rm -v "$PWD":/data -w /data/outputs ghcr.io/rom-py/schism:5.13.0 combine_hotstart7 -i <step>
```

This writes `outputs/hotstart_it=<step>.nc`, which becomes `hotstart.nc` in the next run.

## Checking a run

SCHISM exits with status 0 even when it stops with an error. A run finished when `outputs/mirror.out` ends with `Run completed successfully`. Errors are in `outputs/fatal.error`.

## Building an image

```bash
docker build -t schism:5.13.0 \
  --build-arg SCHISM_VERSION=5.13.0 \
  --build-arg SCHISM_SHA256=<sha256 from releases.txt> \
  docker
python docker/test_image.py schism:5.13.0
```

The build downloads the release from GitHub and checks its checksum. It uses the compiler settings in `docker/schism` (`Make.defs.gfortran`, `include_modules`, `include_modules_wwm`).

## Publishing

`.github/workflows/docker.yml` builds each release in `releases.txt` and runs `test_image.py` in the image. It then publishes the image to `ghcr.io/rom-py/schism`, with `latest` pointing to the last line of the file. Pull requests only build and test. To add a release, add a line to `releases.txt`.
